# Frozen stress tests — start with existing logs

Extract the files into C:\CARLA_0.9.16\PythonAPI\examples\a6_frozen_stress_kit.
The evaluator uses NumPy and threadpoolctl (install with python -m pip install numpy threadpoolctl only if missing). It does not require PyTorch or a CARLA server. The restricted float32 checkpoint reader and independent NumPy GRU/GAT forward pass reproduce the reference confusion matrix on seed2047. The uploaded assisted_model.pt SHA-256 is enforced; a different checkpoint is rejected.

## 1. Existing-log observation dropout

From this new kit folder, with carla_env activated:

    python -u stress_evaluate.py --input ..\outputs\a6_observations_60s --model ..\observation_comparison_kit\observation_comparison_smoke_v1\assisted_model.pt --output dropout_results.json

It evaluates seeds 2047–2049 at missing-observation rates 0%, 25%, and 50%. It skips other seed numbers; use only development data in the input folder. Runs may take several minutes. The evaluator prints each completed seed/rate result. No training, parameter search, source edits or new CARLA runs occur.

If your checkpoint is stored elsewhere, change only --model. Output files must be new. To try one seed first, append --max-runs 1 and use a different output filename.

Dropout removes the observation channels, not the beacon, target label or claimed-kinematics graph. A deterministic per-event mask is reused across overlapping windows; masks are nested across drop rates. This simulates independent observation unavailability, not wireless packet loss or realistic occlusion bursts. No zero-valued physical observation is fabricated: the trained missingness mask is set and normalized physical entries are zeroed. Existing observation-age and causality rules are retained. Observation history may allow the neural detector to predict when the instantaneous rule abstains.

The model threshold remains 0.5; the residual-rule threshold remains 10.48297593814976 m. The latter was chosen from training residual separation. Neither is refitted. Report counts, source hashes and checkpoint hash are recorded. Metrics describe generated local report targets, not RSU/A6 decisions.

For a fair reading, compare neural_rule_covered_reports with residual_rule_covered_reports on identical current-observation coverage, and report rule_coverage/abstentions alongside neural_all_reports. A rule abstention is neither a true negative nor a false negative. If coverage is zero, covered F1/recall/FPR are null.

## 2. Smaller offsets and higher noise — fresh CARLA runs

Do this after the existing-log evaluator runs successfully. Start CARLA and run:

    python collect_stress.py --dry-run

There are 18 development jobs: three seeds (2047–2049) times six conditions: 20m offset/reference noise0.5m, offsets2/5/10m at reference noise, and 20m offset with base noise2/4m. The collector adds its existing distance/power terms to base noise; these are not total sigma values. Smaller offsets are physically generated by the collector, not manufactured by changing graph values or labels.

Start with one reference job:

    python collect_stress.py --max-runs 1

Then collect the remaining jobs:

    python collect_stress.py

Requires ../carla_a6_v5_observations.py and its existing helper files. Uses ../outputs/a6_frozen_stress, fresh per-case folders, and Traffic Manager ports10020 onward. Completed cases are checked and skipped; incomplete folders stop execution. Failures/timeouts stop the runner. Preserve an incomplete folder elsewhere before retrying and check CARLA state. No automatic deletion or retry. Full collector stdout/stderr is in each case's collector.log. The collector dry-run was tested here, but CARLA execution was not.

Evaluate collected physical conditions (without additional dropout initially):

    python -u stress_evaluate.py --input ..\outputs\a6_frozen_stress --model ..\observation_comparison_kit\observation_comparison_smoke_v1\assisted_model.pt --drop-rates 0 --output physical_stress_results.json

The adapter discovery key includes attack/noise configuration to distinguish conditions with the same seed. No other graph construction change is made. Repeated seeds do not guarantee exactly identical traffic trajectories across CARLA reruns; compare both detectors on each same run and summarize across seeds.

## Scientific limits

This is development stress evaluation, not held-out evidence: seeds2047–2049 have already influenced checkpoint selection. Keep seeds2050–2052 untouched until the protocol is fixed. Do not change thresholds or pick a checkpoint based on these stress results without declaring another development cycle. These experiments do not establish superiority over TRE.

All sensing remains synthetic noisy position with ideal association. Passing these tests would not validate real camera/radar perception. All reporters are honest in this stage, while 25% of targets attack their positions. A6 trust and reporter manipulation are separate later experiments.
